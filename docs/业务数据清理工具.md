# 业务数据清理工具

用于清空功能验证产生的业务成果。工具位于 `scripts/clean-business-data.ts`，入口为 `npm run db:clean:business`。默认仅预览，必须显式选择执行并人工确认。

## 清理范围

覆盖所有项目，包含系统内部的通用法规题库。不能按项目或单独选择某类成果。

| 业务 | 删除内容 |
| --- | --- |
| 试卷 | 试卷、试卷明细、考评点关联、试卷结构及版本、组卷计划及版本、抽题槽位、组卷执行记录 |
| 试题 | 全部状态的试题，包括已入库题；版本、选项、答案、来源关联、质量检查、标签关联、状态事件 |
| 命题 | 命题计划、任务、批次、生成单元和槽位、法规命题任务，以及命题/审核/规划模型运行记录 |
| 审核 | 试题审核分配、审核意见、修订关联、入库确认，以及已删除细目表的考评点审核记录 |
| 细目表 | 理论知识细目表、操作技能细目表及其全部版本、节点、来源关联、配额、发布检查、生成和导入记录 |
| 辅助记录 | 关联业务的导出、导出文件关联、下载、通用任务和任务尝试，以及可识别的业务幂等记录 |

**保留**：账号与会话、权限、项目、职业与等级/方向、教材、职业标准、资料版本和解析结果、理论/技能权重表、技能结构表、模型配置、质量标准、法规原文配置、系统设置、题目标签字典、历史审计日志。

职业标准解析结果与权重表共用蓝图存储，因此不清理 `theory_weight` 和 `skill_structure` 类蓝图。工具只清理 `theory_outline` 和 `skill_outline` 类蓝图。重新生成时可以继续使用现有基础配置。

上传文件、原件及磁盘中的生成文件一律不物理删除，`file_objects` 保留。本工具清理的是数据库业务成果，不是文件存储或日志的彻底擦除工具。历史审计中的内容快照也仍然保留。

## 执行前提

1. 部署包含本工具的代码并安装依赖。Node.js 要求 20.12 及以上。
2. 数据库应完成当前项目全部迁移，且清理表使用 InnoDB。缺表或缺少主键会拒绝执行。
3. 停止所有应用实例、PM2 进程、独立 worker、定时任务及其他数据库写入来源。停服必须持续到清理完成。数据库维护锁只阻止多个清理工具同时执行，不能阻止应用写入。
4. 完成全库备份并确认备份可恢复。工具不会自动备份，也没有撤销按钮。
5. 在交互终端执行。禁止管道输入确认，不提供 `--yes` 或无人值守执行。

## 线上操作

在应用目录、使用运行应用的系统账号操作。以下示例基于项目部署手册的 PM2 进程名 `itembank`；数据库名应按实际环境调整。

先预览，可在停服前查看范围，但这时数量可能变化：

```bash
npm run db:clean:business -- --config-file .env.production
```

停服并核对全部实例已停止：

```bash
pm2 stop itembank
pm2 status
```

按部署手册完成 MySQL 全库备份。将备份保存在应用目录以外的受控目录，不要提交到仓库。备份成功后执行：

```bash
npm run db:clean:business -- --config-file .env.production --execute \
  --database itembank --operator "管理员姓名" \
  --maintenance-confirmed --backup-confirmed
```

工具显示目标主机、数据库和各表待删除数量。核对无误后，输入以下完整内容（数据库名不是 `itembank` 时需相应替换）：

```text
清空业务数据:itembank
```

成功后会显示实际删除记录数和审计记录 ID。再预览一次，确认待清理数量均为 0：

```bash
npm run db:clean:business -- --config-file .env.production
pm2 start itembank
```

登录检查：试卷、试题、细目表列表为空；账号、职业、原件、权重及结构配置仍可用。

如果已在终端设置 `DATABASE_URL`，不要同时传 `--config-file`。工具拒绝双重配置来源，避免继承的环境变量覆盖指定文件。可以省略 `--config-file`，直接使用明确设置的 `DATABASE_URL`。

## 安全与异常

- 使用普通事务删除，保持外键检查开启，不使用 `TRUNCATE`，不重置自增计数。
- 清理前固定目标记录的主键集合，根据实际外键排序，先删子表。自关联版本/节点仅对待删除记录解除父级关联。
- 若保留记录或新加业务表仍引用待删除数据，拒绝执行，避免级联误删。需要扩展工具规则后再运行。
- 删除、生成冷却状态重置及成功审计记录在同一事务中完成；提交前发生错误则回滚。审计记录包含操作人声明及每表数量。
- 操作人是命令行填写的留痕信息，不是管理员登录认证。执行权限由服务器和数据库账号控制。
- 如报错，保持停服，先重新预览确认数据库状态，再处理原因。网络在提交瞬间中断时可能无法判定提交结果，应查预览和审计日志，不应仅凭终端退出状态判断。
- 可重复运行。已清空时不会再次删除保留数据，但仍会记录本次成功审计。
- 历史版本和大批量题目会占用事务日志、临时表空间，执行前确认数据库可用磁盘和维护窗口充足。

## 验证

规则及命令行防护测试：

```bash
npx tsx --test scripts/business-cleanup.test.ts
```

真实 MySQL 集成测试仅允许本机数据库，使用唯一前缀的临时测试业务表并在结束后删除；不修改已有业务表。测试账号需要创建/删除表及外键权限：

```bash
RUN_CLEANUP_INTEGRATION=1 node --env-file=.env.local --import tsx \
  --test scripts/business-cleanup.test.ts
```

覆盖预览无写入、保留标准和结构、已入库题清理、修订版本自关联、试卷和导出链路、外键引用保护、审计失败时完整回滚、成功清理及重复执行。
